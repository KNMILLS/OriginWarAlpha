# Inventory stacking

Owner request: matching items should stack in the inventory. Baseline is bd96f4ea911d35ca46f4cf8ebe4636587038e398; existing station art, A.L.I.C.E. speech, audio, oxygen supplies and campaign content remain unchanged.

The core InventoryStacks helper defines a logical slot by item type and exact name, with oxygen/cell power included because it changes the resource delivered. Medicine power is unused by the medicine rules, so identical compounds group regardless of that unused field. Equipment uses actual type-based statistics and groups by type/name. Quantities sum saved quantities, not record counts. First-seen order and original saved IDs/order are preserved; presentation receives copies. No save-format migration is needed.

Capacity is24 logical stacks. A matching pickup can join a full pack; automatic underfoot pickup skips an ineligible new stack to find a later matching item. Explicit item IDs remain strict. Untrusted saves/carried records retain a512-record safety bound, and floor items retain512. Item validity and record limits are checked before grouping. SaveStore invokes the core validator and shares its record bounds.

Use and drop each consume/move one unit. A single-unit drop keeps its original ID. Splitting a saved quantity allocates a short deterministic collision-free ID without using any RNG, preserves the original remaining quantity/ID, and checks floor capacity before mutation. Spare equipment drops before an equipped item; splitting a multi-quantity equipped record leaves its remaining unit equipped. Dropping the final equipped item restores the existing default gear. The UI labels this action explicitly.

Stack selection follows its key after first-record removal changes row order; if a stack disappears, selection moves to the nearest remaining row. Detail pages reset when the selected stack changes. The Pack shows quantity, exact equipped status, per-pack battery strength and Stacks n/24; inspection does not spend a turn. Successful inventory actions retain the existing return-to-station behavior.

Compatibility: schema/envelope remain1; old saves load with original quantities/IDs, subject to existing validity and the new logical capacity. Ordinary quantity1 action fixtures retain their results. Deliberately, DROP on an old quantity greater than1 now drops one unit; hypothetical old multi-quantity DROP replays are not promised equivalent results.
